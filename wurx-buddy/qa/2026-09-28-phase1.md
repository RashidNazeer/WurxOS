### Coverage highlights
- **Grants:** all 8 new functions are SECURITY DEFINER with a pinned `search_path`. None is executable by PUBLIC or anon. `ai_enqueue`, `ai_ingest_claim/complete/fail` and `ai_can_read_document` are denied to `authenticated`, even with a Boss JWT. `ai_search`, `ai_feedback` and `ai_ingest_retry` are executable by `authenticated`. There are no stray overloads.
- **Client writes:** neither a Boss JWT nor anon can INSERT, UPDATE or DELETE any of `ai_documents`, `ai_chunks`, `ai_ingest_queue`, `ai_ingest_runs`, `tts_articles` or `ai_request_log`. The first two are blocked by privilege (42501). The other four are blocked by RLS: inserts get 42501, and updates and deletes touch 0 rows.
- **RLS reads:** the Boss sees the queue, runs and `tts_articles`. The APC and developer see none of them. The APC sees only their own `ai_request_log` row.
- **`ai_feedback`:** a user can rate their own request and cannot rate someone else's (0 rows change). Ratings 0, 2 and −2 are rejected. The note is capped at 2000 characters. anon is denied.
- **`ai_search`:** a null embedding with empty, blank or null text returns 0 rows. An inactive+deleted profile returns 0 rows, both through its own JWT and through the service relay; so do an unknown user, service_role without `p_as_user`, and a JWT with no `sub`. `p_match_count` clamps: 500→100, null→100, 0→1, −5→1, default 30. Each arm caps at 60. The period filter includes a doc whose `period_end ≥ from`, including `= from`, and never returns `status='deleted'` docs. A KB doc with `private` visibility is hidden from an APC. An unknown `acl_mode` is rejected by the CHECK constraint. **Reassignment:** an APC sees a brand's report and brand docs while assigned, and both vanish as soon as the `brand_assignments` row is deleted, with no re-index.
- **v1:** the new NOT NULL columns (`kind`, `meta`, `engine`, `provider`, `ai_messages.meta`) all have defaults. v1 never sends them (checked `ai-chat/index.ts` L1407, L1694, L1698 and `aiAssistantApi.js` L111, L124, L130; `AiAssistantPage.jsx` L271 sends an explicit whitelist), and all 140 existing docs rows are `kind='doc'`. The config row is still `engine='v1'`.

## Bugs / findings

### M1 (medium): a crashing item is reclaimed forever and never reaches `failed`
`369_ai_ingest_queue.sql:107-108`. The stale-reclaim branch (`status='processing' and locked_at < now()-10min`) never looks at `attempts`. An item that kills the worker (timeout, OOM, a huge report) is re-claimed every 10 minutes with `attempts` climbing past 5. It never shows up as `failed` in the health panel, and each retry may re-embed, which costs OpenAI money.
**Repro:** `queue.sql` §4 WARN: "c4 reclaimed with attempts=6, never reaches failed".
**Fix:** in `ai_ingest_claim`, first park exhausted stale rows, then claim only rows under the limit. For example, add a CTE `update … set status='failed', last_error='worker died 5 times' where status='processing' and locked_at < now()-'10 min' and attempts >= 5`, and add `and attempts < 5` to the stale branch.

### M2 (medium, security defence in depth): `kb` mode fails OPEN when `metadata.visibility` is missing
`368_ai_search.sql:39`: `coalesce(d.metadata->>'visibility','office') = 'office'`. A KB document indexed without a `visibility` key is readable by every user. The app's own `kb_select` policy (mig 134:39) and the design (A§4.2, `coalesce(…,'')`) deny it. Today `kb_articles.visibility` is NOT NULL, so this only bites if the Phase 2 extractor forgets the key. That is exactly the kind of bug a fail-closed default exists for.
**Repro:** `search.sql` WARN: "K2 kb no visibility key" is returned to an APC.
**Fix:** `coalesce(d.metadata->>'visibility','') = 'office'`. Add a row to `acl.sql` for it.

### M3 (medium, latent for P2): `ai_enqueue(…, 5)` with an int literal doesn't resolve, and that error is NOT swallowed
`369_ai_ingest_queue.sql:71-73`: `p_priority smallint`. An integer literal has no implicit cast to smallint, so `perform ai_enqueue('report', id, 'upsert', 5)` raises "function does not exist" at call time. That happens outside the function's `exception when others` block. Inside a P2 trigger, it would **abort the user's report save**, breaking the "indexing must never block a save" guarantee.
**Repro:** `queue.sql` §10 WARN.
**Fix:** take `p_priority int` and cast inside (`p_priority::smallint`). `create or replace` can't change argument types, so first run `drop function if exists public.ai_enqueue(text,text,text,smallint,interval,text);`, then re-create it and re-revoke. That keeps the migration idempotent. The alternative is to make `::smallint` mandatory in the P2 trigger review checklist.

### L1 (low): an urgent delete merged into a debounced upsert waits out the debounce
`369:86`: `not_before = greatest(old, now()+p_debounce)`. If an upsert with a 180 s debounce is pending and a `delete` (priority 0, debounce 0) arrives, the row becomes `delete`/priority 0 but still waits up to 180 s. A§9.3 says deletes and ACL changes skip the debounce. The report ACL is checked live, so nobody gains access they shouldn't have. The impact is that a report moved back to draft stays searchable for up to 3 minutes.
**Fix:** `not_before = case when excluded.op = 'delete' then excluded.not_before else greatest(ai_ingest_queue.not_before, excluded.not_before) end`. Optionally do the same for `acl`.

### L2 (low): `ai_ingest_complete` / `ai_ingest_fail` don't check status or owner
`369:121-123` and `369:146-152`. Two cases:
- A worker whose lock was reclaimed can still close a row that another worker now holds (see the `queue.sql` §4 WARN).
- A duplicate `fail` on a `done` or `failed` row flips it back to `pending`.

**Fix:** add `and status = 'processing'` to both updates. Optionally, pass `p_worker` and match `locked_by`.

### L3 (low, defence in depth): four tables keep client write privileges
`369:61-68` (`ai_ingest_queue`, `ai_ingest_runs`), `370:66-70` (`ai_request_log`) and `371:42-46` (`tts_articles`). Supabase's default privileges give `anon` and `authenticated` INSERT, UPDATE, DELETE, TRUNCATE, REFERENCES and TRIGGER, and only RLS stops the writes. TRUNCATE bypasses RLS. PostgREST can't issue a TRUNCATE, so this isn't exploitable today. 367 already revokes on its two tables, so these four should match.
**Fix:** `revoke insert, update, delete, truncate, references, trigger on <table> from anon, authenticated;`. Keep SELECT, since the admin RLS read policies need it.

### L4 (low): `ai_feedback` accepts a null rating
`370:79`: `null not in (-1,1)` is null, so the guard passes and the rating (and note) are cleared. This is harmless, since it only affects the caller's own row, but it's probably unintended.
**Fix:** `if p_rating is null or p_rating not in (-1, 1)`.

### L5 (low): the `db-dev.mjs sql` runner can be made to commit, and still prints "(rolled back)"
`db-dev.mjs:71-76`. A SQL file containing `commit;` ends the runner's transaction. Every statement after it autocommits on dev. The final `rollback` only raises the notice "there is no transaction in progress", and the script still prints `(rolled back)`.
**Repro:** a file containing `commit; select 1;` prints the row, then `notice: there is no transaction in progress`, then `(rolled back)`.
**Fix:** treat that notice as fatal (exit 1 with a loud message). Alternatively, refuse files that contain top-level `commit|end|rollback|begin` statements.

A related problem at `db-dev.mjs:71`: a file saved with a UTF-8 BOM, which PowerShell 5.1 `Set-Content` writes by default, fails with `syntax error at or near "﻿commit"`. **Fix:** `sql.replace(/^﻿/, '')`, and do the same in `apply`.

### L6 (low): the prod guard is a substring test
`db-dev.mjs:30-32`. The guard checks that the URL *contains* the dev ref anywhere and does not contain the prod ref. A URL that points at a host by IP or custom domain, with the dev ref in a query parameter or password, would pass. A connection string with no host would also fall back to the `PGHOST` environment variable. None of this can happen by accident: it needs the prod password in `.env.dev`.
**Fix:** parse the URL. Require `username === 'postgres.' + devRef` (pooler) or `hostname === 'db.' + devRef + '.supabase.co'`, and reject an empty host.

A related point: `ssl.rejectUnauthorized: false` (L35) accepts any certificate. That's acceptable for a dev helper, but worth a comment.

### Design observations (not bugs; for Phase 5/6)
- **D1: the keyword arm is AND-only** (`368:92`, `websearch_to_tsquery`). Every query word must appear in the chunk. `"zqxsrchkw passage"` matched 30 rows, while `"zqxsrchkw passage missingword"` matched 0. The unicode question also returned 0 for the same reason. If Phase 5 passes the raw user question as `p_query_text`, the keyword arm will rarely fire for natural-language questions, so exact-name recall (brands, SKUs) depends on the agent writing short keyword queries. One option is an OR query with `ts_rank_cd` ordering, for example `replace(plainto_tsquery('english', v_text)::text, ' & ', ' | ')::tsquery`. See DECISIONS NEEDED.
- **D2: the period filter drops undated docs** (`368:104-105`). With any `p_period_from` or `p_period_to`, KB, TikTok and guide docs (null period) are excluded. A doc with only `period_start` is compared on its start. This matches the design, but the agent must not attach a period to non-report searches. It should be documented in the tool contract.
- **D3: `kb` ACL has one `author_id`.** `kb_select` also grants access to `submitted_by` (mig 134:33). The P2 KB extractor must decide which of the two goes into `author_id`; the other person loses access in the assistant only.
- **D4:** `ai_can_read_document` uses `urole = 'boss'` rather than `is_boss(uid)` (A§4.2). The two are equivalent, because `ai_search` only resolves `urole` for an active, non-deleted profile.

## Security review summary
- **Injection:** there is no dynamic SQL (`EXECUTE`/`format`) in any Phase 1 function. User text only reaches `websearch_to_tsquery`, which never raises on syntax; the hostile-string test passed.
- **SECURITY DEFINER:** all 8 functions pin `search_path` (`public`, or `public, extensions` for `ai_search`). All table references are schema-qualified. Optional hardening: append `pg_temp` or use `''`. That is low value here, because PostgREST roles can't create objects in `public`.
- **Impersonation:** `p_as_user` is honoured only for `service_role` (covered by acl.sql and search.sql).
- **Secrets:** `.env.dev` is gitignored (`.gitignore:10`). `db-dev.mjs` never logs the URL or password. Error output shows only the pooler hostname and project ref. No secrets are in any test file or in this report.
