## Review points
- **Owner-only RLS.** Verified: only the owner can select, update or delete (not even the Boss can read another user's chat); a client cannot INSERT; client updates are limited to `title`, `pinned` and `last_read_at`; `ai_messages` is read-only for clients. The `title_edited` trigger fires for client renames but not for service-role ones (engineer test).
- **Realtime.**
  - Both tables are in `supabase_realtime`, and RLS is the same one the realtime worker evaluates per subscriber (verified by SQL as other users).
  - Replica identity is the default, so DELETE events, which skip RLS, only carry the uuid.
  - **A live signed-in subscription test was not possible from QA** (no user JWT). The UI polls every 4 s underneath Realtime, so a Realtime failure only slows recovery down.
- **page_context** never names anything the caller can't see (live, above). `kb_id` is never named. The route is limited to URL-path characters.
- **allowed_roles** is enforced. The function reads it with the service role, the default is `{boss}`, and non-Boss callers get 403. On dev it is `{boss}`.
- **Disconnect** leaves no half-finished rows through the local server. **But a function killed by the platform does** (M1).
- **UI role gates** match the RPC rules:
  - the settings entry is shown to Boss and Developer only;
  - "Run ingestion" is shown to both (a Developer sees "stats are Boss-only");
  - Sources, Exclusions, Persona, Knowledge and Slack are shown to the Boss only;
  - RLS and the RPCs enforce all of this anyway.
- **XSS.** Answers go through `renderAssistantHtml`, which escapes, then applies DOMPurify with a tag/attribute allow-list. Citations are fixed button markup. User text, titles and source labels are rendered as React text. External links get `rel="noopener noreferrer"`. Two small gaps: m3 and m4.
- **Clean code checks:** no hardcoded hex colours (`buddy.css` uses tokens and `color-mix`), no `window.location.reload()`, no production URL or key (the endpoint is `VITE_SUPABASE_URL`, or `VITE_BUDDY_URL` for local testing), and no dangling import of `AiAssistantPage` (`/assistant` redirects to `/buddy`).
- **Minimise and navigation never cancel a reply.** `BuddyProvider` wraps `AppShell` above the routes and owns every stream and watcher. The panel stays mounted when hidden. Only the user's Stop, sign-out or the provider unmounting aborts a stream.
- **Cleanup:** every subscription, interval, listener and timeout in the provider, `watchReply`, the FAB and the mascot is cleaned up. One loop is not (m5).

## Issues
**M1 (major, backend): a reply row can stay `generating` forever if the function dies mid-turn.**
- Worst-case turn time is up to 5 model calls × 90 s (`MODEL_TIMEOUT_MS`), with 3 tool rounds, the answer call and the empty-answer retry. That is about 450 s plus tools, above the edge wall-clock limit (150 s on the free plan, 400 s on paid). `waitUntil` does not extend that limit.
- A platform kill, or both `persist` attempts failing (`core.ts:272-282`), leaves the row `generating` with no server-side finisher.
- The UI shows "Buddy lost this reply" after 3 m 15 s, but the database row never settles.
- Fix:
  - bound the turn below the wall clock: a total deadline in `runTurn`, then write the partial answer as `error`;
  - add a finisher that turns rows older than about 10 minutes in `generating` into `error`, either in `ai_housekeeping` or at the start of the next turn.

**M2 (major, backend and UI): Stop only stops the browser.**
- `stop()` aborts the fetch (`BuddyContext.jsx:219-223`), but the function keeps generating and spending: the turn is independent of the connection by design.
- The finished reply then lands, `last_reply_at` moves, and the conversation shows as **unread**: the happy Buddy plus a badge, for an answer the user stopped. The UI note says "The full answer may still appear".
- Fix, one of:
  - server-side cancel, e.g. the client flags the row or conversation and `runTurn` checks between rounds;
  - or treat a stopped conversation as read when its reply lands, and call the button "Hide" rather than "Stop".

**m1 (minor): `BUDDY_ROLES` lists all 8 roles (`buddyLogic.js:11`), while `allowed_roles` on dev is `{boss}`.** Every employee on dev sees the nav item and the FAB. They only get "coming soon" after sending, and their question is dropped. Fix: gate the UI on `ai_assistant_config.allowed_roles` (authenticated users can read it), or narrow `BUDDY_ROLES` until the Lead widens the list.

**m2 (minor, backend): the rate limit counts only finished turns.** The `ai_request_log` row is written at the end of the turn (`core.ts:91-98, 283-289`), so parallel sends get past the 30-per-hour cap.

**m3 (minor, XSS-adjacent): `src/lib/assistantMarkdown.js:22` treats `//host` as an in-app link.** `[x](//evil.example)` passes `startsWith('/')` and becomes `href="//evil.example" data-nav="//evil.example"`, so a middle-click or open-in-new-tab goes to an external site. `sourceLink` already excludes `//`. Fix: `url.startsWith('/') && !url.startsWith('//')`.

**m4 (minor): `citeHtml` (`buddyLogic.js:417`) runs its regex over the whole HTML string, attribute values included.** A `[S1]` inside a link URL breaks the anchor's markup. No script can get in, because the inserted markup is fixed. Fix: replace only in text nodes, or skip matches inside tags.

**m5 (minor): `findNewConversation` loops for up to 30 s** (`BuddyContext.jsx:108-119`) and is not cancelled when the provider unmounts. Harmless, because it checks `inflight` afterwards.

**m6 (minor, performance): `useModalOpen` (`BuddyFab.jsx:88-101`) observes the whole body subtree, attributes included.** While a reply streams, every mutation schedules an `elementFromPoint` plus `getComputedStyle` walk, at most every 150 ms.

**m7 (minor): `server.ts:34` compares `x-internal-secret` with `===`, which is not constant-time.**

**m8 (test gap):** the **deployed** function's `EdgeRuntime.waitUntil` path and Realtime delivery were not tested live as a signed-in user, because QA has no user JWT. The same code passed through the local Node server. The Owner's run on dev covers the rest.
