### What the new assertions pin down
- **M1:** `claim` parks a stuck row with `attempts >= 5` as `failed`, with `last_error = 'worker crashed or timed out 5 times'` and `locked_at` null. It is not reclaimed. A stuck row at `attempts = 4` is still reclaimed (as attempt 5), and a fresh lock at `attempts = 5` is left alone.
- **M3:** `ai_enqueue(…, 5)` resolves and stores 5. `70000` overflows inside the function, so the error is swallowed and no row is written. Exactly one `ai_enqueue` overload exists.
- **L1:** a delete merged into a debounced upsert has `not_before = now()`. A later debounced upsert keeps it `delete` and due now. A new delete ignores `p_debounce`.
- **L2:** a stale worker's `complete` and `fail` both return false, and the row stays `processing`, owned by the new worker, with no error written. `complete` and `fail` on a `done` row return false and cannot resurrect it. A null worker, a pending row and an unknown id all return false. The owner's calls return true.
- **L3:** `anon` and `authenticated` hold none of INSERT, UPDATE, DELETE, TRUNCATE, REFERENCES or TRIGGER on any of the 6 tables, and there are no column-level grants.
- **L4:** a null rating raises `rating must be -1 or 1`, and the stored rating and note are unchanged.
- **M2 / kb (search.sql):** an APC sees only the `office` KB doc. Private, missing-key, JSON-null and unknown (`"everyone"`) visibility are all hidden from the APC. The Boss sees all 5.
- **M2 / kb (acl.sql matrix):**
  - the submitter (`metadata.submitted_by` = the APC) sees a private doc, and so does the service relay acting as the APC;
  - the author (`author_id` = the APC) sees a private doc;
  - private, missing and unknown visibility are hidden from the APC and TL and visible to boss, ol and developer (Lead's decision, same as the mig 134 KB page);
  - `role` visibility with `{tl}` is visible to the TL and not to the APC.
- **D1:** an extra query word that no chunk contains no longer drops matches (30/30). A query where no word matches returns 0 rows. Stop words plus one real word still match. Punctuation- or operator-only text returns 0 rows without error. Ranking is 3 matched words > 2 > 1, and a chunk with none is not returned.

## Review of 372

A missing or JSON-null key goes through `coalesce(…,'')`, and an unknown value matches no branch. `acl_roles` and `acl_users` are NOT NULL (367:31-32), so a null `= any()` can't make the result null. - **OR tsquery:** it is injection-safe. User text only enters through `plainto_tsquery`, whose output contains only quoted lexemes joined by ` & `. A lexeme cannot contain a space, so the `replace` can only touch operators. I checked the actual rewrite output on dev for hyphenated words, URLs with `&`, e-mails, backslashes, apostrophes and numbers: all are well formed. 18 hostile strings raised nothing, including tsquery operators, quote tricks, `' & '` and 50k characters. Empty or stop-word-only input gives an empty tsquery, so `numnode = 0` and the keyword arm is off (tested).
- **Idempotency:** confirmed by re-running.
- **Revokes:** every function has the right EXECUTE set, with no stray overloads, 8 of 8. The old signatures `ai_enqueue(…smallint…)`, `ai_ingest_complete(bigint)` and `ai_ingest_fail(bigint,text)` are gone. Table revokes are confirmed.

## Merge review: can a role-restricted SOP become an `acl: all` document?

**Not through the indexing path.** The reasoning, checked with a throwaway probe against the real modules:
1. `aiDocSkipReason` (aiDoc.ts:37-42) marks every linked doc (`merged into kb_article`) and every unlinked sentinel doc (`fail closed`) as not indexable. `toDocument` throws for both, and does the same for the `app_guide` extractor (a sentinel doc with `kind='app_guide'` is also refused).
2. A linked doc's text only enters `kb.ts`. That happens for the article whose id equals `kb_article_id` (`linkedSops`, kb.ts:68-69), under that article's `kbAcl` and `metadata.visibility`. The probe confirmed that a restricted article carries `mode: kb`, `roles: [ol]`, `visibility: role`, and only its own doc id. A doc linked elsewhere is excluded.
3. The article is indexed only when it is approved and the latest version. Otherwise the SOP text is dropped, which costs recall and never leaks.
4. On dev, all 133 sentinel docs are linked, so no role-restricted text can reach `ai_doc`. The preview confirms this: `ai_doc` indexes 6 docs, all curated.

The only way around it is to call `toDocument` directly on an **inactive** row (L7 below).

## Bugs / findings (all new; all low)

### L7 (low, defence in depth): `aiDoc.toDocument` builds an `acl: all` document for an inactive imported SOP
`aiDoc.ts:38` checks `is_active` first, and `toDocument` (L69) only throws when `skip !== 'inactive'`. So for an inactive doc, the linked and unlinked checks never run.
**Repro:** call `aiDocExtractor.toDocument({ is_active: false, kb_article_id: 'k1', content: '<!--wurx-sop-import-->…' })`. It returns `acl {"mode":"all"}` with the SOP text. Today's callers check `indexable()` first, so this isn't reachable. But the guard exists precisely for a caller that forgets to check, for example a P2 re-extract or delete path.
**Fix:** in `toDocument`, throw on `row.kb_article_id || isImportedSop(row)` regardless of `is_active`. Keep the `inactive` exemption only for curated docs. Add a unit test for it.

### L8 (low, deliberate misuse only): the `sql` runner's rollback proof can be defeated by a crafted file
There are two layers, and both can be defeated:
- **Static check:** `findTxControl` (dev-env.mjs:51) strips `$tag$…$tag$` *before* quoted identifiers. In `select 1 as "$x$"; commit; select 2 as "$x$";` the dollar-quote regex swallows the `commit`, and the check returns `[]` (verified statically; not run against dev).
- **Runtime check:** the marker is an ordinary GUC. After the commit, a file can run `select set_config('dbdev.txn','open',false)` at session level, and the runner then prints `(rolled back)`.

Nobody does this by accident.
**Fix:** use an unforgeable runtime proof. Record `pg_current_xact_id()` (or `now()`, which is fixed per transaction) right after `begin`, compare it before the `rollback`, and treat a mismatch as fatal. Optionally, strip quoted identifiers before dollar quotes.

### L9 (low): an `acl` op merged into a debounced upsert still waits out the debounce
`372:97-98` makes merges due now only for `delete`. A§9.3 says ACL changes also skip the debounce. Unlike reports, the KB ACL is a snapshot in `metadata` (visibility, roles, users, `submitted_by`). If a KB article is tightened from `office` to `role` while an upsert is pending, the old ACL stays searchable for up to the debounce (for example 180 s).
**Fix:** `case when excluded.op in ('delete','acl') or ai_ingest_queue.op = 'delete' then now() …`. Alternatively, accept the window and write that down.

### L10 (low, latent): "latest version" ignores `approval_status`
`sop-match.mjs:53-57` and the preview/loader rule (`chunk-preview.mjs:82`: first row per `sop_group_id` by `version desc`) pick the highest version even when it is pending. When that happens, the approved previous version is skipped as `superseded` and the pending one as `not approved`, so the article and its merged SOP text drop out of the index. Dev has no multi-version groups today, so nothing is affected.
**Fix:** make it "latest *approved* version per group", in the P2 loader and in `pickOne`. That is also the version users can see on the KB page.

### L11 (low, other owners): two scripts don't use the new guard
- `tests/eval/refresh-expected.mjs:25` still has the old substring test (the L6 pattern). This belongs to the other QA instance's area; I didn't touch it. It should call `devDbUrl()`.
- `scripts/profile-data.mjs:16` builds a service-role client from `VITE_SUPABASE_URL` with no host check. It is only exploitable if a prod URL is paired with the dev service key, and that pairing would fail auth anyway. It should check `hostname === devRef + '.supabase.co'`, the way `run-eval.mjs:98` does.

## Notes (not bugs)
- **N1:** a `COMMIT` inside a DO block or procedure is harmless under the runner, because Postgres refuses it inside the explicit transaction. The static filter doesn't need to catch it.
- **N2:** two SOPs have only a `(part 1)` doc on dev ("How to audit a brand", "How to Onboard a Brand (Complete Guide)"). Either the importer cut them off, or the article really is one part. This affects recall only; the Lead may want to check the source docs.
- **N3:** `npm run preview` hung once with near-zero CPU for more than 8 minutes. The pooler probably dropped the socket mid-query, and `c.on('error', () => {})` swallows the drop, so there is no reject and no retry. A second run finished in under 3 minutes. Suggestion: set `query_timeout` / `statement_timeout` on the preview client so the retry loop actually fires.
- **N4:** KB ACL fields are snapshots in `metadata`, so P2 needs `kb_articles` triggers that enqueue `acl` on changes to `visibility`, `visible_to_roles`, `visible_to_users`, `submitted_by`, `created_by` and `approval_status`. Those triggers should be tested the same way `search.sql` tests brand reassignment.
- **N5:** the OR keyword arm will match very common words ("gmv", "brand", "report") in most chunks. The ranking is correct. Whether RRF's equal weighting of that noisy arm hurts precision is a question for the eval (Phase 5/6), not a bug.
- **N6:** a new file, `supabase/migrations/373_ai_ingest_write.sql`, appeared in the tree during this review. It is out of scope and not applied on dev (`db:status` stops at 372). If it adds functions, `grants.sql`'s "all 8 phase-1 functions" list will need extending.
